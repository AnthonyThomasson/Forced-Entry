# AI · Snapshot demand (`snapshot/snapshot_demand.gd`, `snapshot/snapshot_lead_memo.gd`)

What `build()` leaves to be built when the walk reads it (#192 rules 23 to 25). The rest of the snapshot: `snapshot.md`.

`build()` builds what every walk reads and hands the rest to a `SnapshotDemand` (`snapshot["demand"]`), filled with the decision's frozen context and knowledge. It holds: the groups `leads`, `entries`, `search_rooms`, `explore`, `interactions`, `rooms` and the grenade throws (`grenade_throws`: the shots' group, and each analysed hostile's in `options["per_target"][id]`); the facts `leads`, `lead_outside`, `grenade_ready`; the sections `odds` and `exposure` (global and per hostile).
- The planner asks it for what its snapshot lacks (`_group`, `_fact`, `_section` in `decision_planner.gd`: the snapshot's own dictionaries first, so a hand-made snapshot with no `demand` still works). What it builds is stored in those dictionaries, so it is built once; `demand.built` names the groups built (a test reads it to see what a walk read; `grenade_throws:<id>` for a hostile's).
- A reader that wants everything calls `demand.complete()`: `NpcCadence.complete()` / `full_options()` (the debug overlay's `debug_zones`, `debug_state`, `debug_brain`, the spectator card) and tests. `NpcCadence.last_demand` holds the demand; the investigate callout's `lead_pos` is `last_demand.group("leads")`.
- What a group reads live (memory, physics space, nav map) it reads when built, up to a walk's latency after the decision began: a door turned or a sound heard meanwhile is in the group, and the walk neither throws nor loses an option (`ai/decision/lazy_groups_read_live`). What it reads from `ctx` and `know` is the decision's frozen copy. A lazy build equals the eager one (path, options read, text) on a world that does not change during the walk (`ai/decision/lazy_groups_match_eager`). The demand holds the snapshot's dictionaries and no dictionary holds the demand (no reference cycle).
- `grenade_ready` is an existence search (`SnapshotThrows.begin_search` over the sources in order: the shots' origin, then each analysed hostile; each source asks one query per kind carried, a lob clear from where the NPC stands or a throw spot a short walk away, `ThrowScan` / `ThrowSpots.scan_step` via `tactics.throws`, `perception-tactics.md`): it stops at the first throw the NPC could make, and answers from a group already built. `SnapshotDemand.throw_search(block)` begins it in steps (`ThrowSearch`, `throw_search.gd`): a block of `block` raw candidates, the rank pass (when more than `THROW_ROUTES` candidates passed) or one route, `next_kind()` saying which (`ThrowScan.Kind`: BLOCK, RANK, ROUTE, DONE) after the free work (a clear lob, a spot already worked out), `step()` running it. The decision job's **throw piece** drives it, one priced step at a time, so the planner finds the fact in the snapshot's facts; `fact("grenade_ready")` runs the same search to its end. The answer is the same at every block size, and what a search works out (the candidate points, whether a spot exists) is kept in the build's `throw_memo` for the full groups built after it. Each step re-asserts the build's own scratch (`open()`) like any lazy read. The throw options are built only when the walk reads them. Tests: `ai/decision/lazy_groups_match_eager`, `ai/grenade/grenade_ready_matches_full_search`, `ai/decision/throw_piece_matches_whole` (the stepped search at 1, 7, 16 and 1000 candidates a block).
- A heard lead's walk (route length and snapped point; gunfire and footsteps) is kept by `SnapshotLeadMemo` for the belief window (`tuning.decision.belief_redecide_interval`), keyed on its two ends. The memo is dropped when the window ends, when the planning map's or its ring's iteration changes (`NavBuilder.iterations`, interface 9: a re-bake swapped in) and when the doors' state changes (`SnapshotLeadMemo.door_state`: each `doors` group member's `angle()` and `is_down()`, read once per physics frame). A walk still being baked (`pending`) is not kept. `pass_clear` memory (a room cleared) is not in the key: it can age out inside the 0.5 s window. Tests: `ai/perception/lead_route_memo_matches_plain`, `ai/perception/lead_memo_follows_ring_rebake`.
