29. **Main → General, Objects, Vehicles, Character: `TwinSpace`, the twin 3D space** (`general/twin_space.gd`, `general/twin_shapes.gd`; `MatchBuilder.stage` builds it; ADR 0014).
    A 3D physics space beside the 2D simulation holding a 3D twin of each solid 2D body, kept in step with it each physics frame. The 2D simulation is the truth and nothing in gameplay reads a twin yet: the
    real-cover jobs read it rule by rule (a bullet's 3D ray, a fragment, a throw, a sight line), then the bodies flip to 3D one class at a time and the direction reverses (ADR 0014).
    - **The space:** `TwinSpace` (`class_name`, a `Node3D` named `Twins`, child of the match's world; Main's `MatchBuilder.stage` makes one per world, so a match and a test world have one, headless too). Its
      twins join the 3D world of the viewport it stands in (the main window's `World3D`, the 3D counterpart of the 2D space the sim runs in, not the 3D view's picture): `space() -> PhysicsDirectSpaceState3D`, and
      the static `TwinSpace.space_of(node) -> PhysicsDirectSpaceState3D` (any node of the sim in the tree) is what a reader casts into. The 3D engine is Jolt (`physics/3d/physics_engine`, `project.godot`).
    - **Reading a hit:** `TwinSpace.owner_of(collider: Object) -> Node2D` maps a ray or shape result's `collider` (a twin) to the 2D body it stands for (null for anything else), so a bullet then calls that body's
      `get_surface()` (3); `twin_of(body) -> Node3D` the other way (null for a body with none). Layers: `PhysicsLayers.TWIN_WORLD` (walls, floors, furniture, doors), `TWIN_VEHICLE`, `TWIN_CHARACTER`, `TWIN_ALL` (11);
      a twin is on its layer only while its body's `collision_layer` is not 0 (a dead character, a knocked-down door) and a seated character's capsule is disabled. Heights are px above the floor on
      `RenderConfig.unit` (`PlanSpace`, 11): walls 96, a door's leaf 84, a floor slab's top at the ground (a road a kerb below), furniture its `PieceHeights` parts (28), a vehicle its body's belt, a character its posture's head top (`BodyHeights`).
    - **The hook:** `TwinSpace.builders: Array[Callable]`, each `Callable(node: Node2D) -> Node3D`, set before `watch`. For each physics body (and each member of a group `track_group` names: the floors have no
      body) the first builder that answers a node wins, null passes on. The node is a `CollisionObject3D` with its shapes built in code in the frame of the 2D body's origin (`TwinShapes.lift_body(body, twin, base, top)`
      lifts a body's own 2D shapes, `TwinShapes.box(rect, local, base, top)` / `lift(shape, local, base, top)` one footprint) on a `collision_layer` of `PhysicsLayers.TWIN_*`, `collision_mask` 0. A plain `StaticBody3D` is
      placed once; an `AnimatableBody3D` (`sync_to_physics` off) follows. A node with `twin_update(body: Node2D)` has it run each frame it follows (a character's capsule follows its posture). Each domain registers its own
      (`register(space)`) and Main wires them in `MatchBuilder.stage`: Objects' `ObjectTwins` (walls, doors, floors, solid furniture, anchored pieces static), Vehicles' `VehicleTwins`, Character's `CharacterTwin`.
    - **The update rule** (`TwinSpace.update()`, once a physics frame at `PRIORITY` -100, before every body's own script): each followed body's `global_transform` is read and its twin written **only when it changed**; a sleeping
      `RigidBody2D` is skipped (read once more as it falls asleep); a body that never moves is written once, when twinned; one that joins the tree is twinned on the next update; one that leaves frees its twin. A reader finds
      a twin exactly where the 2D step left a rigid body or a door, and a body a script moves one frame (1/60 s) behind. Read-outs: `count`, `followed`, `written`. A dent does not reshape a twin.

      `tests/vehicle/twin_vehicle_follows_test.gd`, `tests/character/twin_capsule_posture_test.gd` (helper `tests/_general/twin_probe.gd`).
