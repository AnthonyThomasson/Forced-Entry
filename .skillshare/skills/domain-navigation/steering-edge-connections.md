# Navigation: the steering map's edge-connection pass

Side file of `domain-navigation` (`SKILL.md`); the welded tiles it rests on: `district-tiles-and-avoid.md`.

The pass (`NavSeams`, `navigation/steering_routes_match_edge_connections`): the server joins polygons by shared edges and then runs a pass joining free edges of different regions within `default_edge_connection_margin` (1 px), which rebuilds the whole map's links on every change: ~10.6 ms a sync of the 42-tile district (measured on welded tiles: 10.6 ms with the pass, 0.32 ms without, whether one tile or five changed; roughly quadratic in the regions: 21 tiles 2.3 ms, 10 tiles 0.45). With the tiles welded (`district-tiles-and-avoid.md`) the pass is **still on** for the steering map: an all-pairs route comparison, pass on against off, over every tile's probe point and both ways across every seam edge (`seam_probe.gd`) is the same path to the point on 17 of 24 seeds, a few other districts and a lone house, but not on the rest: 7 of the 24 answer 11 to 172 of ~2000 routes differently, the pass off never the longer, never missing a destination, the most under by 224 px (seeds 24, 4, 6, 2, 17, and by under half a pixel 1 and 14). In the one route looked into, the route with the pass on bends at the end vertex of a shared edge where the one with it off crosses mid-edge; the cause is not proven. Turning the pass off (`NavSource.new_map` for the steering map) changes how NPCs steer in those routes, so it waits for the user's decision.
