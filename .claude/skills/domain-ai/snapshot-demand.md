# AI · Snapshot demand (`snapshot/snapshot_demand.gd`, `snapshot/snapshot_lead_memo.gd`)

What `build()` leaves to be built when the walk reads it (#192 rules 23 to 25). The rest of the snapshot: `snapshot.md`.

`build()` builds what every walk reads and hands the rest to a `SnapshotDemand` (`snapshot["demand"]`), filled with the decision's frozen context and knowledge. It holds: the groups `leads`, `entries`, `search_rooms`, `explore`, `interactions`, `rooms` and the grenade throws (`grenade_throws`: the shots' group, and each analysed hostile's in `options["per_target"][id]`); the facts `leads`, `lead_outside`, `grenade_ready`; the sections `odds` and `exposure` (global and per hostile).
- The planner asks it for what its snapshot lacks (`_group`, `_fact`, `_section` in `decision_planner.gd`: the snapshot's own dictionaries first, so a hand-made snapshot with no `demand` still works). What it builds is stored in those dictionaries, so it is built once; `demand.built` names the groups built (a test reads it to see what a walk read; `grenade_throws:<id>` for a hostile's).
- A reader that wants everything calls `demand.complete()`: `NpcCadence.complete()` / `full_options()` (the debug overlay's `debug_zones`, `debug_state`, `debug_brain`, the spectator card) and tests. `NpcCadence.last_demand` replaces the old `last_options`; the investigate callout's `lead_pos` is `last_demand.group("leads")`.
- What a group reads live (memory, physics space, nav map) it reads when built, up to a walk's latency after the decision began; what it reads from `ctx` and `know` is the decision's frozen copy. The demand holds the snapshot's dictionaries and no dictionary holds the demand (no reference cycle).
- `grenade_ready` is an existence search (`SnapshotThrows.grenade_possible` / `shots_possible` over `AgentTactics.has_throw_spot`, `perception-tactics.md`): it stops at the first throw the NPC could make, and answers from a group already built. The throw options are built only when the walk reads them. Tests: `ai/decision/lazy_groups_match_eager`, `ai/grenade/grenade_ready_matches_full_search`.
- A heard lead's walk (route length and snapped point; gunfire and footsteps) is kept by `SnapshotLeadMemo` for the belief window (`tuning.decision.belief_redecide_interval`), keyed on its two ends. The memo is dropped when the window ends, when the planning map's `map_get_iteration_id` changes (a re-bake swapped in) and when the doors' state changes (`SnapshotLeadMemo.door_state`: each `doors` group member's `angle()` and `is_down()`, read once per physics frame). A walk still being baked (`pending`) is not kept. `pass_clear` memory (a room cleared) is not in the key: it can age out inside the 0.5 s window. Test: `ai/perception/lead_route_memo_matches_plain`.
